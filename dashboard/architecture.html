The Hawkes H

Two strokes and a bar. Studio turns what people want into code that ships, using AI agents. Gen turns requests into files, using rented machines. They exchange jobs and evidence across one bar. Below is the H with every part opened, and one change traced through it in twelve steps.

One change, twelve steps

  1. The owner says what they want. It goes through the edge to Talk.in: words
  2. Talk writes it down. A roadmap item, tasks, and what "done" means for each.solid: criterion rows
  3. The loop starts an agent. The router picks a tier and a harness and launches one disposable job.out: one command line
  4. The agent returns its work. A stream of events while it runs, then its commits.back: event stream + commit bundle
  5. Studio opens the pull request and merges. After the project's checks pass, the change lands on beta.solid: commits on beta
  6. The hook reports the push. The code host tells Studio which repo and branch moved.in: a signed token
  7. The publisher rebuilds the beta site. Only changed files are sent.solid: files named by git id + a manifest
  8. Studio asks Gen to build and play it. When a milestone's tasks are all merged, or on a go-live request.across: job specs
  9. Gen runs the jobs on workers. A build machine builds; a browser plays the game's own bot; a model reviews the footage.solid: assets in the library
  10. Evidence comes back. Outcome, footage, scores and a yes or no per criterion. Studio keeps ids, not files.across: report + verdict JSON
  11. The gate moves main. Only for the exact commit that was played, and only on the owner's word.solid: main fast-forwarded
  12. The live site updates. The code host serves whatever main points at.out: the published site

A failed step loops back instead of forward: a failed check or a "no" from the judges sends the task back to step 3, up to three tries, and then to the owner.
